# 09 工程文件格式（.pvproj）设计

> 作者：program｜日期：2026-10-23｜状态：设计稿，待用户确认后实现
> 依据代码：`Core/SceneObject.cs`、`MeshData.cs`（SceneNode / SceneLight / SceneCamera / SceneWorld）、`OrbitCamera.cs`、`ModelViewport*.cs`、`OutlinerItem.cs`。字段名与代码一一对应，代码变了以代码为准并同步本文。

## 1. 目标

像 Blender 的 `.blend` 一样，把"当前工作状态"存成一个文件，重新打开后恢复：

- 场景里有哪些对象（导入的模型、Shift+A 添加的灯光），各自的位置/旋转/缩放；
- 节点级的显示/隐藏（`SceneObject.HiddenNodes`）、对象显示（`SceneObject.Visible`）；
- 集合（Collection）的勾选框 / 眼睛 / 禁用渲染三个开关；
- 灯光参数、相机、World 环境光；
- 视图状态：轨道相机、透视/正交、着色模式、线框；
- 选中对象、场景列表展开状态、界面语言。

非目标见 §12。

## 2. 扩展名

| 文件 | 说明 |
|---|---|
| `*.pvproj` | 工程文件（PolyView Project） |
| `*.pvproj1` | 上一次保存的备份（同 Blender `.blend1`），每次保存前把旧文件改名为它 |
| `*.pvproj.autosave` | 自动保存，放在 `%LOCALAPPDATA%\PolyView\autosave\` |
| `*.pvproj.tmp` | 原子写入用的临时文件，写完即改名，不应残留 |

## 3. 容器选型

| 方案 | 优点 | 缺点 |
|---|---|---|
| A. 纯 JSON（只存路径） | 最简单、可读、可 diff | 源模型被移动/删除就打不开；不能单文件分享 |
| B. JSON + 链接外部文件（相对路径） | 文件小；源模型更新后自动生效 | 同 A，拷到另一台电脑要连目录一起拷 |
| C. **ZIP 包**（推荐） | 单文件可分享；可内嵌原始模型；可放缩略图和网格缓存；.NET 自带 `System.IO.Compression` | 不能直接文本 diff（可解压查看） |
| D. 自定义二进制 | 最快 | 维护成本高、难调试 |

**结论：采用 C，ZIP 包内放 `project.json` 清单；每个源文件可选"内嵌"或"链接"。**

- 默认 **内嵌**（Embed）：把导入时的原始文件（及 glTF 的 `.bin`/贴图、OBJ 的 `.mtl`/贴图等伴随文件）原样存入 `assets/`。打开时从包内解压到缓存目录再走现有导入器，保证与导入时完全一致。
- 可选 **链接**（Link）：只存相对工程文件的路径 + 绝对路径兜底 + 哈希。适合几百 MB 的大模型。
- 不存我们自己的网格二进制作为唯一数据源：原始文件 + 现有导入器就是"真相"，避免 MeshData 结构一改旧工程全废。网格二进制只作为可选缓存（§11）。

### 包内结构

```
scene.pvproj (zip)
├── project.json           必需，清单（UTF-8，无 BOM）
├── thumbnail.png          可选，256×256 视口截图，用于资源管理器/最近文件
├── assets/
│   ├── a1b2c3…/car.glb    内嵌源文件，按 sha256 前 16 位分目录，避免重名
│   └── d4e5f6…/house.obj
│       house.mtl, tex.png 伴随文件放同一目录，保持相对引用
└── cache/                 可选，网格缓存（见 §11），缺失不影响打开
```

## 4. project.json 结构

约定：长度单位米；旋转存四元数 `[x,y,z,w]`（与 `ObjectTransform.Rotation` 一致，不丢精度），界面上的欧拉角只是派生；灯光的角度存**度**（与 Blender 界面一致，代码里 `OuterConeAngle` 是半角弧度，序列化时换算）；颜色为线性 RGB `[r,g,b]`。

### 4.1 顶层

| 字段 | 类型 | 说明 |
|---|---|---|
| `format` | string | 固定 `"PolyView.Project"` |
| `formatVersion` | int | 当前 `1`，见 §9 |
| `appVersion` | string | 保存时的程序版本，如 `"0.3.0+c7f9948"` |
| `savedAt` | string | ISO 8601 带时区 |
| `units` | object | `{ "system": "metric", "scaleLength": 1.0 }` |
| `assets` | array | 源文件列表 §4.2 |
| `collections` | array | 集合 §4.3 |
| `objects` | array | 场景对象 §4.4 |
| `world` | object | §4.6 |
| `viewport` | object | §4.7 |
| `selection` | object | §4.8 |
| `ui` | object | §4.9 |

### 4.2 assets（源文件）

```json
{ "id": "asset-1", "mode": "embed",
  "entry": "assets/a1b2c3d4e5f60718/car.glb",
  "companions": ["assets/a1b2c3d4e5f60718/car.bin"],
  "originalPath": "F:\\models\\car.glb",
  "relativePath": "..\\models\\car.glb",
  "sha256": "a1b2c3d4…", "size": 1834221, "format": "glb" }
```
`mode` 为 `"link"` 时没有 `entry`/`companions`，按 `relativePath` → `originalPath` 顺序查找。

### 4.3 collections

```json
{ "id": "col-1", "name": "Collection", "parent": null, "expanded": true,
  "included": true, "visible": true, "renderable": true }
```
对应 `OutlinerItem.InitCollection(included, visible, renderable)`：`included`=勾选框（取消则子对象全部隐藏且不可拾取），`visible`=眼睛，`renderable`=禁用渲染的相机图标。现在只有一个默认 Collection，结构上允许嵌套，为以后多集合留口。

### 4.4 objects（对应 SceneObject）

```json
{ "id": 1, "name": "car", "kind": "model", "asset": "asset-1",
  "collection": "col-1", "parent": null,
  "importOffset": [0.0, 0.42, 0.0],
  "transform": { "location": [0,0.42,0], "rotation": [0,0,0,1], "scale": [1,1,1] },
  "visible": true, "renderable": true, "expanded": false,
  "hiddenNodes": [3, 7],
  "nodes": [ { "index": 5, "name": "Light.001", "light": { … 覆盖值 … } } ] }
```

- `id`：保存时的 `SceneObject.Id`。打开时**重新分配** id（`_nextId++`），用映射表修正 `parent` / `selection`，所以 id 只需文件内唯一。
- `kind`：`"model"`（有 asset）或 `"light"`（Shift+A 添加，无 asset，用 `light` 字段重建，即 `AddLight` 的构造逻辑）。以后可加 `"camera"`、`"empty"`。
- `importOffset`：仅做校验——重新导入后若与 `MeshData` 算出的偏移不一致（源文件变了），提示"源文件已更改"。
- `hiddenNodes`：`MeshData.Nodes` 的下标。为抗源文件变化，同时存节点名路径（`"nodePaths": ["Root/Wheel_FL"]`），下标对不上时按路径匹配。
- `nodes[]`：文件内灯光/相机节点被用户修改过的参数（以后属性面板做好后用），没改过不写。

### 4.5 灯光（kind = light，对应 SceneLight）

```json
"light": { "type": "spot", "color": [1,0.95,0.9], "power": 1000.0,
  "radius": 0.1, "spotSize": 45.0, "spotBlend": 0.15,
  "areaShape": "square", "areaSize": [1,1] }
```
`type`: `sun | point | spot | area`（`Directional`↔`sun`）。`power` 点/聚/面光为 W，日光为 W/m²（`Power`）；`spotSize` = `OuterConeAngle×2` 换成度。

相机节点（`SceneCamera`）以后若允许添加独立相机：`{ "orthographic": false, "yFov": 39.6, "orthoHalfHeight": 0, "near": 0.1, "far": 100 }`。

### 4.6 world

```json
"world": { "color": [0.05,0.05,0.05], "strength": 1.0, "fromFile": false }
```
`fromFile=true` 表示来自导入文件；用户改过就写 false 并以这里为准。

### 4.7 viewport（对应 OrbitCamera 等）

```json
"viewport": { "camera": { "target": [0,0.5,0], "yaw": 0.785, "pitch": 0.35,
    "distance": 6.2, "fov": 45.0, "orthographic": false },
  "shading": "solid", "wireframe": false, "showGrid": true, "showNavGizmo": true }
```
`yaw/pitch` 弧度（与 `OrbitCamera` 一致），`fov` 度。`shading`: `wireframe | solid | material | rendered`（着色模式按钮做好后启用，旧版本忽略）。

### 4.8 selection

```json
"selection": { "active": 1, "selected": [1], "activeNode": -1, "tool": "move" }
```

### 4.9 ui

```json
"ui": { "language": "zh", "outlinerFilter": "", "outlinerScroll": 0,
  "window": { "width": 1600, "height": 900, "maximized": true } }
```
窗口尺寸只在用户勾选"加载界面"（默认开，同 Blender Load UI）时恢复。

## 5. 保存流程

| 操作 | 快捷键 | 行为 |
|---|---|---|
| 文件 > 保存 | Ctrl+S | 有路径直接保存，没有则走"另存为" |
| 文件 > 另存为 | Ctrl+Shift+S | 选路径；内嵌/链接选项在对话框下方（默认内嵌） |
| 文件 > 保存副本 | — | 写到别处，但当前路径不变（后做） |

步骤：
1. 从 `ModelViewport` 取快照（新增只读 API `CaptureProjectState()`，在 UI 线程拿值，数据量小）。
2. 后台线程：计算 asset 哈希（导入时已算过就复用）、写 ZIP 到 `xxx.pvproj.tmp`；内嵌文件用 `CompressionLevel.Fastest`（glb/png 本身已压缩，可用 `NoCompression`）。
3. 写完 `Flush(true)`，若旧 `xxx.pvproj` 存在则改名为 `xxx.pvproj1`（覆盖旧备份），再把 `.tmp` 改名为 `xxx.pvproj`（`File.Move(..., overwrite)` / `File.Replace`），保证任何时刻断电都至少有一份完整文件。
4. 成功：清除脏标记，状态栏显示"已保存 xxx.pvproj"，加入最近文件列表。失败：删 tmp，弹窗显示原因，旧文件不受影响。

**脏标记**：`SceneChanged`、变换提交（进 undo 栈时）、可见性、灯光、World 修改时置脏；标题显示 `* scene.pvproj - PolyView`。视角、选中变化**不**置脏（同 Blender，但仍会被保存）。关闭窗口、新建、打开其他工程时如果脏，弹"保存 / 不保存 / 取消"。

**自动保存**：每 2 分钟（可设置）且脏时，后台写到 `%LOCALAPPDATA%\PolyView\autosave\<名字>_<pid>.pvproj.autosave`，链接模式写（不重复打包大文件）。正常退出时删除；启动发现残留则在 文件 > 恢复 > 自动保存 中列出。

## 6. 打开流程

入口：文件 > 打开（Ctrl+O，过滤器加 `PolyView 工程 (*.pvproj)`，与模型格式并列）、拖放 `.pvproj` 到窗口、命令行 `PolyView.exe scene.pvproj`（并可在安装时注册文件关联）、最近文件。

规则：打开 `.pvproj` = **替换**当前场景（先问是否保存）；打开模型文件仍是现有的导入行为。

步骤：
1. 打开 ZIP，校验 `format`，读 `formatVersion`（大于当前版本时提示"由更新版本创建，部分内容可能丢失"，仍尽量打开）。
2. 迁移到当前版本（§9），反序列化为 `ProjectModels`。
3. 解析 assets：内嵌的解压到 `%LOCALAPPDATA%\PolyView\cache\<sha256>\`（已存在且哈希一致则跳过）；链接的按 相对路径 → 原绝对路径 → 工程同目录同名文件 查找，找到后比对哈希，不一致只警告。
4. **缺失文件**：汇总成一个对话框"以下 N 个文件找不到"，每行可 [重新定位…]（选中后同目录其他缺失文件自动按文件名尝试）、[跳过]。跳过的对象保留为占位（灰色、名称后加"(缺失)"），再保存时保留其记录，不丢数据。
5. 复用现有异步加载管线（`LoadPaths`）逐个导入，导入完成后依次应用：Transform → HiddenNodes → Visible → 集合开关 → 灯光覆盖值；Shift+A 灯光直接重建。
6. 全部完成后恢复 World、视口相机、着色、选中、场景列表展开，触发一次 `Invalidate()`（避免启动灰屏那类问题），清空 undo/redo，清除脏标记。
7. 进度显示在状态栏"正在打开 3/7：car.glb"，可取消（取消则回到空场景）。

## 7. 错误处理

| 情况 | 处理 |
|---|---|
| 不是 ZIP / 没有 project.json | "不是有效的 PolyView 工程文件" |
| JSON 解析失败 | 报行列号；提示可尝试打开同目录的 `.pvproj1` 备份 |
| 单个 asset 导入失败 | 记入汇总报告，其余继续，该对象作为占位保留 |
| 数值非法（NaN、缩放为 0、四元数长度 0） | 用默认值替换并在报告中列出 |
| 保存时磁盘满 / 无权限 | 删 tmp，保留旧文件，弹窗 |
| 所有异常 | 写入 `%LOCALAPPDATA%\PolyView\crash.log` 同目录的 `project.log` |

## 8. 安全

- **Zip Slip**：解压每个条目时 `Path.GetFullPath(Path.Combine(dest, entry.FullName))` 必须以 `dest + 分隔符` 开头，否则拒绝；拒绝绝对路径、`..`、盘符、设备名。
- **Zip 炸弹**：限制条目数（≤ 10000）、单条解压大小（≤ 4 GB，且不超过声明大小）、总大小；压缩比 > 200 的条目警告。
- 只解压 `project.json` 里 `assets` 引用到的条目，其它条目忽略。
- 不执行包内任何内容；链接路径只读取，不写入。
- JSON 用 `System.Text.Json`，`MaxDepth` 64，不启用多态类型名反序列化。

## 9. 版本与迁移

- `formatVersion` 整数，只在**不兼容**变化时 +1；加可选字段不升版本。
- `ProjectMigrator`：按 `JsonNode` 逐级 `v1→v2→…` 迁移，每步一个函数，带单元测试样例文件 `tests/projects/v1_*.pvproj`。
- 保存总是写当前版本；打开旧版本后标题加"(已从旧格式转换)"，首次保存前提示会升级格式。

## 10. 与现有代码的对应 / 需要补的 API

| 需要的数据 | 现有位置 | 要补 |
|---|---|---|
| 对象列表、Id、Name、SourcePath、Transform、Visible、HiddenNodes | `ModelViewport._objects`（`SceneObject`） | `CaptureProjectState()` / `ApplyProjectState()` |
| 新加灯光 | `AddLight` 中构造 `SceneLight` | 抽出 `CreateLightObject(SceneLight, transform)` 给加载复用 |
| 视角 | `_camera`（`OrbitCamera`） | 读写接口 |
| 线框 | `Wireframe` 属性 | — |
| 选中 | `_selectedId`、`SelectNode` | 已有 `Select` |
| 集合开关、展开 | `OutlinerItem`（`InitCollection` / `SetExpandedSilently`） | 状态目前在 UI 里，需上移到场景模型（如 `SceneCollection` 类），场景列表只做显示 |
| 源文件的伴随文件 | 导入器内部（glTF bin、OBJ mtl、贴图） | 导入器返回"实际读取过的文件列表"，用于内嵌 |
| undo 栈 | `_undo` / `_redo` | 打开工程时清空 |

## 11. 性能

- 哈希：导入时顺带算 SHA-256（流式），存在 `SceneObject` 上，保存时不再读一遍大文件。
- 缓存：解压目录按哈希命名，同一模型再次打开不重复解压。可选 `cache/<sha>.pvmesh`（MeshData 二进制：顶点/索引/Parts/贴图 BGRA，带 MeshData 版本号）——格式稳定后再做，版本不符就回退到重新导入。
- 多个对象并行导入（受现有加载管线限制，先串行，后续再并行）。
- 保存在后台线程，UI 不卡；缩略图从当前渲染目标读回缩放到 256。

## 12. 不在本期范围

- undo/redo 历史（同 Blender，不存）；
- 动画、骨骼姿态、时间轴；
- 材质编辑结果、修改器、网格编辑（目前没有这些功能）；
- 多场景、链接/追加其他工程（Blender 的 Link/Append）；
- 窗口布局 / 工作区编辑。
