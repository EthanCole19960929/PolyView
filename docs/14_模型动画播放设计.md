# 14 模型动画播放设计

> 日期：2026-10-25（UTC+8）  
> 状态：设计稿，尚未实现。本文按当前代码结构提出最小可用方案。

## 1. 目标与范围

给导入的模型提供动画片段查看和播放能力，让用户能在 PolyView 中选择片段、播放、暂停、停止、循环、调整速度和拖动时间轴。播放过程中继续支持视口导航、选择和场景内对象变换。

第一阶段是**动画播放器**，不是动画制作器：不创建/编辑骨骼，不改关键帧，不做动作混合、重定向或物理模拟。MVP 先支持 glTF 2.0 / GLB 中的节点 TRS 动画和骨骼蒙皮动画；FBX、DAE、Morph Target/Blend Shape 与多段动作混合放到后续阶段。

## 2. 当前实现与主要缺口

- `GltfImporter` 遍历节点、网格和 skin，读取 JOINTS/WEIGHTS，并以 `inverseBind * joint.WorldMatrix` 得到导入时的蒙皮矩阵；随后将位置/法线烘焙进普通 `Vertex[]`。它不保存 skin、动画 clip 或可变形顶点数据。
- `MeshData.Nodes` 保存节点名、父子关系和导入时 Local/World 矩阵，但没有动画通道或原始网格局部空间数据。
- `SceneRenderer.AddMesh` 为普通静态顶点创建 GPU 顶点缓冲；目前没有骨骼索引/权重输入、姿态求值或每帧顶点更新机制。
- `AssimpImporter` 同样把节点变换烘焙进顶点，当前没有读取 `aiAnimation` 并保留骨骼动画数据的路径。
- `.pvproj` 通过嵌入原始模型文件恢复模型。导入器具备动画数据后，工程可以从已嵌入的 GLB/GLTF 重新构建 clips；工程对象目前还没有“当前动画片段”等播放设置。
- `ImportOptions` 中已有 FBX “Animation”选项，但这只是导入选项数据/界面，不代表动画已经被解析或播放。实现前应确认其当前可见性与文案，避免向用户暗示功能已完成。

因此不能只加播放按钮：必须先让导入数据保留节点动画、蒙皮权重和绑定姿态，再让渲染器根据当前姿态变形。

## 3. 用户体验

在视口下方增加可折叠的时间轴区域，默认在导入含动画的模型并选中它时可见；普通静态模型不占用时间轴空间。时间轴包含：

- 当前对象与动画片段下拉选择（显示片段名、时长）。
- 播放 / 暂停、停止、循环开关、播放速度（建议 0.1×–4×）。
- 当前时间输入和时间滑块；拖动时立即预览姿态，松开后按播放状态继续或保持暂停。
- 可选的起止范围显示；MVP 默认使用片段完整时长，不提供剪辑/关键帧编辑。
- 片段为空时显示简洁空状态，例如“此模型没有可播放的动画”。

对象切换、工程打开、导入新模型时，时间轴跟随活动对象更新。播放不应更改对象 TRS、产生撤销记录，也不应每帧把工程标记为“已修改”。

## 4. 数据与求值模型

### 4.1 导入数据

将动画资源从当前的扁平静态 `MeshData` 中分离出来，并让 `MeshData` 保留可供动画驱动的原始结构。建议的概念模型：

```text
MeshData
  Vertices / Indices / Parts / Textures        静态网格继续使用
  Nodes[]                                      原始局部空间节点层级
  Skins[]                                      joint 节点索引、inverse bind matrices
  SkinBindings[]                               mesh 节点到 skin 的绑定关系
  AnimationClips[]                             名称、时长、采样通道

AnimationClip
  Name, DurationSeconds
  Channels[]: TargetNode, Path, Interpolation, Times[], Values[]
  Path: Translation | Rotation | Scale | Weights（Weights 延后）
  Interpolation: STEP | LINEAR | CUBICSPLINE

SkinBinding
  MeshNode, SkinIndex, VertexJoints[], VertexWeights[]
```

glTF accessor 数据须在导入阶段复制到 PolyView 自有托管数组，不能在 SharpGLTF 模型释放后仍引用其内部对象。通道中的旋转用四元数，translation/scale 用 Vector3；CUBICSPLINE 须保留每个 key 的 in tangent、value、out tangent。采样时对时间区间二分查找，STEP 取前一键，LINEAR 对向量线性插值、对四元数做球面插值，CUBICSPLINE 按 glTF Hermite 规则计算并归一化旋转。

为避免扩大内存占用，静态模型沿用现有 `Vertex[]` 和静态 GPU buffer；只对有 skin 的 primitive/mesh 保存原始局部坐标、关节索引、权重及绑定数据。无动画或无 skin 的部分不增加 per-frame 成本。

### 4.2 姿态求值

每个播放时刻从导入的 bind/rest Local TRS 开始，采样 clip 通道并覆盖其目标属性，再按父节点顺序计算节点世界矩阵。未被片段控制的属性保持 bind/rest 值。多个 glTF scene root 按各自原始层级独立求值。

对蒙皮顶点，先在 CPU 上验证矩阵约定和 glTF 参考样例，再确定最终公式。PolyView 的场景矩阵约定是 System.Numerics 行向量；不能把当前静态导入时的 `inverseBind * joint.WorldMatrix` 直接套用到新流水线，因为当前 mesh 顶点已被变换/蒙皮烘焙。姿态求值应从 mesh 局部顶点出发，结合 joint 当前世界变换、inverse bind matrix 和 mesh 节点空间，生成正确的 mesh-local 位置与法线。

非蒙皮节点动画也要可见：对节点动画，渲染时使用动画求出的节点世界矩阵，而不是继续使用导入时已经烘焙到顶点的世界坐标。MVP 可选择两种内部路径：

1. **推荐：**保留 node-local 网格，按节点 world matrix 绘制；蒙皮网格单独走 skinning 路径。这样节点动画自然适配场景节点。
2. **短期过渡：**导入时缓存每个 part 的原始局部顶点，动画每帧在 CPU 上变形/重算节点变换，再更新动态顶点缓冲。实现简单，但 CPU 成本和重复数据较高；只适合作为低顶点数模型的过渡方案。

建议先做可正确验证的 CPU 姿态/蒙皮基线，再按数据量引入 GPU skinning。GPU skinning 需要扩展顶点格式（JOINTS/WEIGHTS）、HLSL 输入和骨骼矩阵常量/结构化缓冲，设置骨骼数量上限或分批策略；不可默默截断导致模型错误。超过上限时先回退 CPU 路径或给出明确提示。

### 4.3 时间与播放状态

每个活动模型对象有播放控制状态：`ClipId`、`TimeSeconds`、`Speed`、`Loop`、`IsPlaying`。播放时用 `Stopwatch`/单调时钟计算 delta，不以定时器 tick 次数累计时间；切换窗口、调试暂停或长时间失焦后限制单次 delta，避免时间突然跳跃。

- 非循环播放到末尾时停在最后一帧并进入暂停。
- 循环播放以片段时长取模；零时长 clip 不能进入播放状态。
- 停止回到 0 秒并显示第一帧；暂停保留当前时间。
- 速度变化从下一帧开始生效；seek 立即求值一次。
- 不播放时维持按需渲染。只有播放或拖动时间轴时才持续请求帧；暂停后移除活动帧回调。

## 5. 渲染与线程

WPF、D3D11 和 `D3DImage` 当前在 UI 线程上协调。动画时钟和姿态求值应由 `ModelViewport` 的渲染回调驱动，保证场景状态更新与渲染顺序一致；MCP/后台调用通过现有命令调度回 UI Dispatcher，不直接从后台线程操作 D3D 资源。

动画每帧流程：更新播放时间 → 采样 channels → 算 node world / skin pose → 更新动态数据或骨骼缓冲 → `Invalidate()`/渲染 → D3DImage 更新。播放激活时允许连续绘制，暂停后恢复现有 `_dirty` 按需渲染策略。渲染热路径避免 LINQ、临时数组和逐帧分配；姿态数组、GPU buffer 复用。导入解析可继续后台执行，完成后再把不可变动画数据交给 UI 线程安装。

首版性能目标：普通静态场景行为和资源占用不变；播放模型在常见角色骨骼规模下保持交互流畅；高顶点数 CPU 蒙皮需设清楚的性能提示，并以 GPU skinning 作为正式性能路径。性能目标需通过项目现有 `--bench` 扩展或独立基准实测确定，不能预先承诺固定 FPS。

## 6. 工程文件、撤销与导出

- 继续由 `.pvproj` 嵌入原始 GLB/GLTF 资产，打开工程时由新导入器重建 clips 和 skin 数据；这样不必把可重复生成的动画通道再复制到 `project.json`。
- 在 `ProjectObject` 增加可选动画播放偏好（活动 clip 的稳定标识/名称、速度、循环、时间）。若产品体验决定打开工程时一律暂停，则保存 clip、时间、速度、循环并始终将 `IsPlaying=false`，避免重新打开工程后意外自动播放。旧项目字段缺省时使用停止状态，保持向后兼容。
- 片段标识不能只依赖可变的下拉索引；优先用 asset id + clip 索引/稳定名称，名称冲突时保留索引。
- 播放时间和 GPU 姿态缓存是运行时状态，不写入撤销栈；暂停/播放/seek 命令不触发几何编辑撤销。
- 当前导出器主要从 `MeshData` 导出静态网格。首版导出只输出当前姿态/绑定姿态静态网格并在 UI/MCP 返回中说明动画未随导出；后续若要 FBX/glTF 动画导出，单列功能设计和验收，不能把静态导出描述成动画导出。

## 7. MCP 与命令接口

遵循项目规则：每个可操作功能用 `[PvCommand]` 注册，UI 与 MCP 复用同一实现。推荐接口（对象 id 省略时作用于当前活动对象）：

| 命令 | 参数/效果 | 撤销 |
| --- | --- | --- |
| `animation.list_clips` | 返回对象的片段 id、名称、时长、目标类型 | 否 |
| `animation.play` | 可选 `clip_id`；开始或继续播放 | 否 |
| `animation.pause` | 暂停并保留时间 | 否 |
| `animation.stop` | 停止并 seek 到 0 | 否 |
| `animation.seek` | `time_seconds`，范围裁剪至片段时长，立即更新姿态 | 否 |
| `animation.set_loop` | `enabled` | 否 |
| `animation.set_speed` | `speed`，限定为正数和产品支持范围 | 否 |

`scene.get` 可增加只读 `animation` 字段（片段名、时长、当前秒数、播放/循环/速度），不返回大型采样数组。命令须校验对象/clip 是否存在、参数是否有限且在范围内；没有 clip 时返回可读错误。播放/暂停/seek 都是可逆的运行时视图控制，不属于危险/破坏性操作。

## 8. 分阶段实施

### 阶段 A：数据管线与正确性基线（P0）

- 定义动画、skin、原始局部网格数据结构；glTF/GLB 导入并保留 clip / channel / inverse bind / 权重。
- 暂不改 UI，先让导入结果能列出 clip、时长、通道数量，并能在 0 秒计算原样 bind pose。
- 用包含节点 TRS、STEP/LINEAR/CUBICSPLINE、多个 joint、多个 skin 的小型 glTF 样例校验采样与矩阵空间。

### 阶段 B：glTF/GLB 播放 MVP（P0）

- 实现节点动画与 skin pose 求值、CPU 参考蒙皮；添加 play/pause/stop/loop/speed/seek 状态。
- 接入按需渲染的播放帧循环；播放中持续刷新，暂停后停止持续帧回调。
- 增加时间轴和活动对象/clip 选择，处理无 clip、零长度、丢失资产、导入错误。

### 阶段 C：工程与 MCP（P1）

- `.pvproj` 重新导入时恢复 clip 列表；保存活动片段、时间、速度、循环偏好（默认打开工程暂停）。
- 注册本设计第 7 节命令；让 `scene.get` 可观察状态。
- 验证 UI 与 MCP 对同一对象的并发操作串行化在 UI 线程，选中对象变化后命令目标明确。

### 阶段 D：性能和格式扩展（P1/P2）

- 将 skinning 从 CPU 参考实现优化到 D3D11 GPU 路径，按实测加入骨骼矩阵缓冲和兼容上限。
- FBX/DAE：基于 Assimp animation、node channel、bone offset 和权重保留完整层级，禁止继续把动画模型简化为不可逆的静态烘焙数据。
- 再评估 Morph Target/Blend Shape、动画混合/重定向和带动画导出。

## 9. 验收清单

- 导入无动画静态模型：界面和渲染行为不变，无额外持续重绘。
- 导入带节点动画模型：节点位置、旋转、缩放按采样时间正确变化；未动画节点保持导入姿态。
- 导入蒙皮 GLB：播放前 bind pose 与现有显示一致；播放时关节、网格和法线不分离、不爆裂；回到 0 秒可复现初始姿态。
- 验证 STEP、LINEAR、CUBICSPLINE、四元数插值、不同动画时长、多个 clip 和通道缺省属性。
- 播放、暂停、继续、停止、循环、速度、拖动 seek 均按预期；末尾/零时长/失焦/切换对象处理明确。
- 播放期间可正常旋转视角、选择对象、变换对象；播放不会污染撤销栈、对象 TRS 或工程 dirty 状态。
- 保存并重开 `.pvproj` 后片段可重建，按约定恢复偏好且不自动播放；老工程仍可打开。
- MCP 命令能列出和控制 clip，`scene.get` 能读状态；无效对象/片段/参数返回错误而非崩溃。
- 暂停/停止后没有逐帧刷新；高负载模型的 CPU/GPU 耗时有实测记录，资源在删除对象、关闭工程、退出时释放。

## 10. 主要风险与决策点

1. **空间/矩阵约定错误：** 当前 glTF 导入结果是世界空间、且可能已蒙皮烘焙。动画路径必须改为保留局部数据；使用标准测试文件比对关键时刻顶点和姿态。
2. **项目模型重构：** 现有静态 `MeshData` 被渲染、拾取、框选、导出、工程保存多处使用。优先加动画专用数据和兼容静态路径，避免动画一期迫使所有静态模型走 skin pipeline。
3. **FBX 选项误导：** 当前 `FbxImportAnimation` 选项存在但未被 `AssimpImporter` 消费。阶段 A 可先将其隐藏/禁用或明确“暂不支持”，等 FBX 数据链完整后再开放。
4. **CPU 蒙皮性能：** 每帧改写大量 CPU 顶点会与按需渲染目标冲突；用 CPU 实现作为正确性基线，性能目标依靠 GPU skinning 与实测。
5. **时间轴 UI 面积：** 时间轴应可折叠，并在无动画时收起；避免静态查看器被永久占用。
